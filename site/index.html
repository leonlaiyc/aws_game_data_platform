02 / 04

FOUR PAINS → FOUR RESPONSES

每個服務選擇，都要能回到一個營運問題

面試時我會先講「誰被什麼問題卡住」，再展示自動化、治理與證據；不是先背 AWS 服務名稱。

M1 DETECTION

異常與套利偵測

痛點

留存／營收下滑太晚才被人工發現；新型套利手法難以辨識。

架構回應

每日 DAU/GGR、週級成熟 cohort 留存，共用 SNS → 診斷路徑；已知規則只標示 REVIEW_REQUIRED。

  • 警報保留 actual、baseline、threshold 與 evidence window
  • 未知套利模型因缺少審核 labels 而明確不宣稱
核心模組
M2 EXPERIMENT OPS

實驗運營平台

痛點

多款遊戲同時做 A/B testing，必須等站會或逐一問人才知道狀態。

架構回應

中央 registry 顯示 owner、生命週期、SRM、guardrail 與 allocation；IAM 身分產生 provenance。

  • 關閉 allocation 與 exposure 寫入使用同一筆 transaction
  • 共享 feature registry 降低不同實驗重算相同特徵
M3 NL ANALYTICS

Analytics NL Assistant

痛點

老闆、業務與客戶的突發問題不好用 dashboard 回答，持續打斷分析師。

架構回應

允許清單 SQL 回答 what；diagnose 重用 first-look 回答 why；答不了就建立 durable ticket。

  • 沒有 free-form text-to-SQL，tenant scope 只來自身份
  • 所有數字由 code render，模型只寫質性文字
M4 PARTNER SUPPORT

合作夥伴支援 Chatbot

痛點

不同時區、不同整合方向的夥伴反覆詢問相似問題，客服答不了又轉給工程師。

架構回應

IAM 身分選擇 provider/operator 隔離語料；clarification、escalation、leakage guard 都由 code 決定。

  • 每個受眾每日最多 50 個有效 paid-path 請求
  • API 全域 0.1 req/s、burst 2，未知身份 fail closed

03 / 04

THE HARDEST REQUIREMENT

不要讓作品集變成一張失控的帳單

架構不是服務越多越好。每個預設資源都必須回答：閒置會不會收費？什麼指標才值得升級？

STEADY-STATE GROSS MODEL < $2 / month

固定成本主要來自 13 個 CloudWatch alarms；不是 compute。

模型值 <$2 $5 預算警報
✓

預設部署

Lambda、Athena、DynamoDB on-demand、Step Functions、EventBridge、SNS/SQS。沒有流量就近乎不產生 data-plane 成本。

×

刻意排除

NAT Gateway、RDS、OpenSearch、Redshift、EMR、常駐 Kinesis 與向量資料庫；目前規模沒有合理化其固定成本。

!

短生命週期例外

Kinesis 只可用明確 flag 執行 deploy → demo → destroy → verify，不可能被預設 deploy --all 意外建立。

面試追問：為什麼沒有 Redshift、Spark 或向量資料庫？

因為我能說出採用門檻，而不是為了履歷放進一個還不需要的服務。

HONEST BOUNDARIES

我不會把還沒做到的事藏起來。

  • 沒有真實產品 ingestion，因此不宣稱端到端 freshness SLA。
  • 沒有 reviewed labels，因此不宣稱能抓未知套利手法。
  • 沒有 partner IdP contract，因此 M3/M4 外部 federation 尚未 production-ready。

THE INTERVIEW TAKEAWAY

我想展示的不是「我用了多少 AWS 服務」。

而是我如何把營運摩擦翻譯成可治理的系統、如何讓 LLM 留在可控邊界內，以及如何在每個架構決策前先算成本與風險。
